--- ANSWERS FOR LAB 04 - SECTION 1.3 ---

1. Compare the top-level containers in Swing and AWT:
- In AWT, the top-level container is `Frame`. Components are added directly to the Frame using `add()`.
- In Swing, the top-level container is `JFrame`. Unlike AWT, lightweight components cannot be added directly to the JFrame. They must be added to its content-pane (a java.awt.Container) using `getContentPane().add()`.

2. Compare the class name of components in AWT and Swing:
- AWT components use standard names without prefixes (e.g., TextField, Label, Button).
- Swing components are easily identifiable as their class names are prefixed with the letter 'J' (e.g., JTextField, JLabel, JButton).

3. Compare the event-handling of Swing and AWT applications:
- The event-handling mechanism is virtually identical in both libraries. Both utilize the `java.awt.event` package (like ActionListener, ActionEvent) and use the exact same listener interfaces and event classes.

4. Compare the resulting appearances:
- AWT uses heavyweight components that rely on the native operating system's GUI peers. Therefore, an AWT application looks exactly like a standard app on the OS it runs on (e.g., looks different on Windows vs. macOS).
- Swing uses lightweight components that are painted by Java itself. This allows a Swing application to have a consistent appearance across all platforms, and it supports pluggable "Look and Feel" themes.
